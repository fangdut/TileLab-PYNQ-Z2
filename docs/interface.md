# 通信 数据流与结果关联

依据当前`tools/fpga_texture_v170/board_client.py`、`experimental/transport_v200/firmware/`和工作站控制器整理。下述项目路径均以`project/pynq_z2_tile_v1_53/`为根。此文是源码导航，不取代线协议实现。

## PC与PS

TCP默认目标`192.168.33.10:9136`。每个请求新建连接，请求和响应头为16个32位小端字，共64字节。请求魔数`0x16905458`，响应魔数`0x16905258`。头部最后一个字为前60字节CRC32。

| 请求字索引 | 字段 |
|---|---|
| 0–3 | 魔数、操作码、请求序号、负载字节数 |
| 4–7 | 偏移、宽、高、负载CRC32 |
| 8 | 身份/模型校验参数，按操作含义使用 |
| 9–14 | 保留 |
| 15 | 头部CRC32 |

原图不由PC缩放：解码为RGB，每像素以32位小端字保存`0x00RRGGBB`，宽高各1到1024。模型先按SHA256和graph信息核验，再分块上传并提交CRC；已匹配模型可复用。操作5为单图推理，其他操作与状态/自动重启能力以客户端和固件为准。

响应校验请求序号、PL身份`0x17000001`、头CRC和负载CRC；单图结果另核对模型CRC、输入RGB CRC、原图尺寸、完成步数47、网格尺寸28及掩膜像素数。结果负载依次为16个32位元数据字、28×28分数字和原图大小的掩膜字。分数按有符号32位解释，掩膜元素只能为0或1。

## PS与PL

| 区域 | 地址 | 用途 |
|---|---|---|
| 硬件身份 | `0x41200000` | 镜像核验 |
| 推理控制 | `0x43c10000` | 地址、尺寸、启动与状态 |
| 原图DDR | `0x06000000` | 原图RGB |
| 结果DDR | `0x07000000` | 评分、掩膜与序号 |
| 模型DDR | `0x08000000` | 751760字节冻结模型 |
| 工作DDR | `0x10000000` | 2408448字节特征工作区 |

PS校验并设置输入，PL从DDR读取后执行完整图，完成后PS校验返回。检测核心及AXI使用PS FCLK_CLK0的100MHz；历史HDMI像素时钟属于独立通路。

## 对应关系与异常处理

检测请求逐件串行执行，匀速界面可在等待时继续移动，用请求序号、板端帧序号、启动身份及输入/参照指纹绑定数据，不使用跨设备时钟对时，不声称实现多传感器时间同步。网页8793端口是本机工作站入口，与板端9136端口不同。

仅建立连接、尚未发出请求字节时允许最多3次连接尝试。请求发送后断连、CRC或身份不符不自动重放检测。系统清除旧可处置结果；换参照、板卡重启、源图变化、旧会话或复核冲突均阻止沿用旧结果放行。8793原单张工作站要求人工正常复核后逻辑放行；8794匀速流水线按下述V208策略对有效未报警结果自动通过。脚本模拟复核与真实人工复核须在记录中区分。


## V208流水线控制

8793为单一板端后端，8794为模拟流水线与截图界面。当前截图SHA和工件编号绑定同一次PL结果，移动位置单独同步。automatic_release只允许有效核验下当前未报警且未经人工处置的结果；处置前再次核对模型和启动编号，review保持空，另写automatic_decision。报警、迟到和冲突不得自动通过。

本机HTTP状态读取可有限重试，并使用加大的连接队列。上传、推理、复核、处置不盲目重发；Board客户端只在尚未发送请求的连接建立阶段重试。临时故障不能恢复旧良品结果。
