# FPGA engineering status — 2026-10-20

Latest physically verified: V170 HLS15 / HW05 / SW07, boot 1348147017. PYNQ-Z2 processed all 117 original MVTec Tile development photos: 84/84 anomalies including 17/17 cracks; 0/33 normal false alarms. All integer scores and original-size masks exactly match the frozen reference. These repeatedly exposed images are a development benchmark, not independent validation.

Measured fixed-frame PL auto-restart: 33 frames in 7.711191 seconds = **4.279494 FPS**, one ARM start. Mean single-image core time 0.233733 seconds. Earlier HLS11 measured 2.695 FPS and the FP32 baseline about 553 seconds per image. No build is yet accepted at the first 10 FPS target or as continuous HDMI video.

The complete reproducible verified package is deliverables/V170_Verified_FullPL_4p28FPS_R1.zip, SHA256 8e50561cf2779efe76d33e14d37b3df7bfa901a6f98240f38a6dbc813cf421bc. Manifest hashes, ZIP CRC, actual unit vectors and frozen source were checked. reports/v170/hls15_verified binds source/model/BIT/XSA/ELF/physical results. Earlier verified snapshots remain preserved.

Runtime PL performs resize, normalization, CNN, pooling, projection, normal-codebook distance search, smoothing, alarm and mask. PC decodes/transports/displays; ARM transports/CRC/configures/times. No CPU/GPU detection fallback. All board programming is volatile JTAG, not Flash.

The current source continues experimental fabric-address work following HLS23. HLS20 adds explicit DDR bursts; HLS21 caches preprocessing coordinates; HLS22 reuses projection RAM for pointwise input tiles; HLS23 retains overlapping depthwise rows in a circular buffer. HLS20–23 each passed all 117 exposed-photo C score/mask comparisons and two-launch RTL/CNN feature checks. The HLS23 static logical convolution-read estimate falls from 22,735,328 to 9,368,672 bytes, including repeated tile-weight reads; it excludes other stages and is not a measured speedup. Further address scheduling is under verification. Use hls/frozen/v170_hls15.cpp or the verified ZIP for the accepted physical snapshot.

The HDMI chain includes native ROI acquisition, async FIFO, DDR commit after write responses, PL HLS scheduling, header/sequence verification and a whole-tile alarm border. Three-frame integrated bus-model simulation passed; this is not CNN or on-board video proof. Earlier failed timing reports remain preserved. HLS20 / V171 HW03 / SW02 has closed actual 100 MHz timing: setup 0.040 ns, hold 0.031 ns, DRC errors 0 and FIFO bus skew pass. Actual use is 39,766 LUT, 217 DSP, 127 BRAM tiles. BIT/XSA/ELF identities are recorded in reports/v171/hls20_timing_closed; no new board programming succeeded because USB Serial Converter B reports Code 10 and JTAG inventory is empty. HLS23 integration is building, with actual DSP capacity checked after synthesis before routing.

CDC exceptions target verified first-stage level synchronizers and reset PRE pins; no blanket asynchronous clock groups disable FIFO Gray-bus constraints. One CDC-10 structural hint remains for the audited combinational reset request into an asynchronous-assert/four-stage synchronous-release bridge. Do not claim zero CDC critical reports.

video_control.py requires a full physical regression matching the exact programmed build and boot, then halts both ARM cores and enables PL once. It reports observed capture/CRC/completion progress without CPU per-frame starts. video_snapshot.py dumps a stopped, drained frame and validates the physical capture CRC and result header. audit_captured_reference.py independently rebuilds the frozen Python model bytes and compares a saved input/result offline, so HDMI-scaled pixels are not confused with original-photo references. None of these pending live-video checks establishes accuracy or throughput before execution. Control addresses are explicitly mapped for both PS and the PL master.

Image decisions do not establish crack tracing: historical abnormal-mask mean IoU approximately 0.519, crack mean IoU approximately 0.067. Arbitrary painted/mixed materials, independent physical validation, continuous-video throughput and competition final acceptance remain open.
