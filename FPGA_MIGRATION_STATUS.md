# FPGA engineering status — 2026-10-21

Latest physically verified detector: HLS23 / V171 HW04 / SW03, boot 3871513087. PYNQ-Z2 processed all 117 original MVTec Tile development photos: 84/84 anomalies including 17/17 cracks; 0/33 normal false alarms. Every integer score and original-size mask matches the frozen reference. These repeatedly exposed images are a development benchmark, not independent validation or proof for arbitrary painted/mixed materials.

Measured fixed-frame PL auto-restart: **6.299218 FPS**; mean single-image core time 0.158803 seconds. Actual HDMI input was also observed with both ARM cores halted at the beginning, middle and end: 45 detections in 8.271 seconds, **5.440696 FPS**, with no CPU per-frame start writes. Fixed-frame speed and HDMI speed are separate measurements. Neither meets the first sustained 10 FPS target.

Runtime PL performs HDMI ROI capture, clock crossing, DDR commit, scheduling, resize, normalization, CNN, pooling, projection, normal-codebook distance search, smoothing, alarm and mask. The input PC decodes and displays original photos. ARM performs startup/model transfer only and can be halted during the video experiment. JTAG reads observations; it performs no pixel detection. All board programming is volatile, never Flash. Debugger disconnect can resume ARM cores, so halt evidence applies to each explicitly checked observation session.

Actual HDMI color fidelity remains an accuracy issue: an independently captured gray calibration pattern has white RGB [251,208,162]. A real normal input falsely alarms without correction. Startup black/white gains Q8 [260,314,403], derived without photo labels or threshold tuning, lowered that saved normal input's offline score from 12359 to 9783 (threshold 10908). This is offline feasibility, not physical correction proof. New V172 RTL applies the correction per pixel in FPGA fabric. It passed all-level integer, saturation, pipeline timing, coherent configuration, pixel-clock interruption, AXI strobe/ownership and integrated bus-model checks. Standalone synthesis uses 380 LUT, 300 registers and **0 DSP**. The integrated V172 HW02 build is pending; no corrected-image accuracy is claimed yet.

HLS23 physical implementation closes 100 MHz timing: setup 0.082 ns, hold 0.050 ns, DRC errors 0, both FIFO Gray-bus skew directions pass. Actual use is 41,221 LUT and 219 DSP. Source/model/BIT/XSA/ELF/boot and full physical results are bound in reports/v171/hls23_verified. Later HLS26 fabric-address scheduling passes all 117 C arithmetic checks and two-launch RTL but fails physical setup timing at -0.864 ns; that candidate must not be programmed or presented as accepted. Failure evidence remains preserved.

CDC exceptions target verified first-stage level synchronizers and reset PRE pins. No blanket asynchronous clock groups disable FIFO Gray-bus constraints. One CDC-10 structural hint remains for the audited combinational reset request into an asynchronous-assert/four-stage synchronous-release bridge. Do not claim zero CDC critical reports. V172 adds a native XPM coherent configuration handshake and requires fresh physical CDC/timing review.

video_control.py binds the full 117-photo physical regression to the exact programmed build/boot, halts both ARM cores and enables PL once. V172 additionally verifies startup color coefficient acknowledgement/readback and unchanged configuration. video_snapshot.py rehalts both cores, dumps a disabled/drained frame and validates capture CRC/result headers. audit_captured_reference.py rebuilds the frozen Python model bytes and checks the saved actual HDMI input/result offline. A physical gray-pattern snapshot passes with zero score error and zero mask mismatches. This proves numeric equivalence, not photo detection accuracy. video_photo_series.py performs controlled settled original-photo experiments without CPU detection or per-frame starts; the uncorrected 117-photo physical run completed: 84/84 anomalies detected, but all 33 normals falsely alarmed. Both ARM cores were checked halted 119 times. This is a failed end-to-end accuracy baseline and is preserved in reports/v172/uncorrected_hdmi117. Corrected HDMI accuracy remains unverified.

The earlier complete verified package remains deliverables/V170_Verified_FullPL_4p28FPS_R1.zip (SHA256 8e50561cf2779efe76d33e14d37b3df7bfa901a6f98240f38a6dbc813cf421bc). It is preserved as the 4.279494 FPS baseline, not silently relabeled as the newest hardware. HLS20–23 optimizations reduce DDR traffic through bursts, coordinate tables, pointwise input tiles and depthwise row buffers. The static logical convolution-read estimate drops from 22,735,328 to 9,368,672 bytes; this excludes other stages and is not a measured speedup by itself.

Image decisions do not establish crack tracing: historical abnormal-mask mean IoU approximately 0.519, crack mean IoU approximately 0.067. Independent real-photo validation, accurate HDMI input decisions, sustained 10 FPS, arbitrary painted/mixed materials and competition final acceptance remain open.
