V173 includes an experimental complete packed CNN kernel, isolated from the accepted HLS23 source. HLS30 processes two output-channel groups with the same 128 multiplier count, uses wide RAM words, and preserves full-width codebook squares. All 117 original-photo C scores/masks match exactly; two complete RTL calls pass (656,435 cycles each for the small 80-side RTL fixture, not full-resolution FPS). Actual isolated synthesis uses 47,618 LUT, 65,515 FF, 218 DSP and 133 BRAM tiles. **Whole HDMI implementation failed**: shared DDR used 57,091 LUT after ExploreArea versus 53,200 available, and further remapping used 57,131. A split-port variant reduced synthesis LUT from 58,640 to 57,379, but detailed placement still rejected instance packing. Neither was programmed. These failures are retained under reports/v173/hls30_full_video_rejected and hls30_split_video_rejected. HLS27/28 were rejected for 334 BRAM18; HLS29 RTL was deferred while reducing area.

HLS31 rearranges bilinear mask interpolation without rounding: vertical interpolation is computed once per grid column per output row, then each pixel reads two cached values. A 176,000-case independent integer/range check and all 117 full C scores/masks pass. HLS32 further narrows convolution sums/packets to 24 bits after proving the active accumulator-plus-bias bound is 5,742,667 < 8,388,608; all 117 C scores/masks also pass. Their HLS synthesis completes, but neither has full RTL or whole-video acceptance. HLS34 applies only the separable mask to the physically accepted HLS23 baseline: all 117 C scores/masks match and two complete RTL calls pass. Its input fixture is 13x9 with internal side 64; it is not full-resolution speed evidence. HLS33 used a source-identical kernel but failed C-wrapper vector generation because the large fixture exceeded declared simulation pointer depths; the matching fixture and an early capacity guard fix that test configuration. Complete HDMI hardware for HLS34 is being compiled. No new board FPS is claimed.

HLS35 separately concatenates two narrow cached pointwise rows in existing line memory, leaving the 128-multiplier array and 32-slot accumulation recurrence intact. It skips pairing at an odd final row and writes contiguous output rows within each channel-group plane. All 117 original-photo C scores/masks match; a 79x65/internal-side-80 odd-row fixture also matches all 5,251 output words. RTL/resource/physical acceptance is still required.

HLS36/37 generalizes this to bounded power-of-two row batches, constrained by the existing 2,048-word line RAM, 224-word quantization row and available cached rows. C real-crack and odd-row checks pass; full-photo regression is running. HLS36 synthesis estimates 219 DSP/250 BRAM18. A legacy-project resume failed C-wrapper linking before RTL; its helper and failure logs are preserved under reports/v173/row_batches37. The unsupported resume helper was retired. HLS37 was interrupted during synthesis and its partial log is preserved. Source-identical HLS38 is running a fresh complete flow using absolute file paths. All 117 original-photo C scores and masks now match exactly; the resumed invocation revalidated 80 saved results and computed 37 remaining cases. Neither is accepted board hardware.

The centered packed kernel requires encoder weights in [-127,127]. Its exhaustive mathematical check covers 16,646,400 activation/weight triples. Build preflight checks every convolution weight against the actual binary model and graph descriptors (529,760 bytes, zero -128 values), and proves active signed24 accumulators (8,052 active channels, 12 zero-multiplier channels). Negative checks reject both an injected -128 weight and an excessive active bias. Zero-multiplier channels produce exactly zero despite unused accumulator wrap. The earlier general INT8 arithmetic primitive also covers -128, with all 16,777,216 triples checked, and remains separately documented.

Coarse on-board phase polling of accepted V172 found approximately 28.86 ms capture/wait, 12.52 ms preprocessing/first convolution, 39.76 ms depthwise convolution, 64.63 ms standard/pointwise convolution, 3.61 ms residual addition and 33.96 ms feature head/mask per frame. These host-polling estimates are not cycle-accurate timings. Both ARM cores were checked halted; there were no HLS control reads or per-frame start writes. This profiling is evidence for selecting future bottlenecks, not a new speed benchmark.
