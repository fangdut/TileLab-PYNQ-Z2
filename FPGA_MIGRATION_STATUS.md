# FPGA engineering status — 2026-10-21

Latest physically verified: V172 HW02 after physical_repair01, HLS23, software from v172_acceptance02, boot 142768567. All 117 original MVTec Tile development photos pass the original-file board regression with exact integer scores and masks. Actual HDMI input also classifies 117/117 correctly: 0/33 normal false alarms, 84/84 anomalies, 17/17 cracks. These repeatedly exposed photos are a development benchmark, not independent validation or proof for arbitrary painted/mixed materials.

Sustained actual HDMI observation: **1386 autonomous detections / 254.101 seconds = 5.454524 FPS**, 117 distinct captured photo CRCs. Both ARM cores were checked halted 119 times during this session; there were no CPU per-frame start writes or CPU/GPU detection. Fixed-frame auto-restart separately measures **6.299142 FPS**. The first sustained 10 FPS target remains unmet.

Runtime PL performs startup-parameter color correction, HDMI ROI capture, clock crossing, DDR commit, scheduling, resize, normalization, CNN, pooling, projection, normal-codebook distance search, smoothing, image alarm and mask. PC decodes/displays source photos and records results. ARM performs startup/model transfer and can remain halted during video detection. Offline Python model checks are separate scientific audits, not runtime inference. All programming is volatile JTAG, never Flash. Debugger disconnect can resume ARM; halt claims apply to explicitly checked observation sessions.

The uncorrected HDMI baseline detects all anomalies but falsely alarms on **all 33 normals**. Independent gray calibration measured black RGB [0,0,0], white [251,208,162], giving Q8 gains [260,314,403]. The new FPGA module applies these gains per pixel. A real normal photo physically changes from score 12359/alarm to 9783/normal; the crack example scores 19273/alarm. Model SHA256 remains 1501e32e733b566e17d125613d0989c04291b658459d63b826e418f6f713ed65, threshold remains 10908. No defect labels were used to derive the gains. Saved good/crack HDMI inputs and actual PL results pass independent reference audits with zero score error and zero mask mismatches. The captured gray ramp reproduces all 256 levels within one output level per channel after correction.

V172 closes actual 100 MHz timing after postroute physical optimization: setup 0.016 ns, hold 0.050 ns, DRC errors 0, both FIFO Gray-bus skew directions pass. Actual use: **40,960 LUT, 219 DSP, 127 BRAM tiles**. Initial V172 setup -0.040 ns is preserved. Physical repair changes placement/routing without model, clock or logical algorithm changes. Vivado export changes only BIT DATE/TIME headers; configuration payload/design/part equality was checked before selecting the XSA-embedded BIT as the canonical external file. Final whole-file BIT/XSA SHA equality remains mandatory. Source/model/BIT/XSA/ELF/boot, hardware reports and experiment hashes are recorded in reports/v172/verified_hdmi.

CDC exceptions target verified synchronizer first-stage D and reset PRE pins. No blanket asynchronous clock groups disable FIFO Gray-bus constraints. The new coherent XPM configuration handshake is recognized in the physical CDC report. One reviewed CDC-10 structural hint remains for the existing combinational reset request into an asynchronous-assert/four-stage synchronous-release bridge; do not claim zero CDC critical reports.

V173 now includes an experimental complete packed CNN kernel, isolated from the accepted HLS23 source. HLS30 processes two output-channel groups with the same 128 multiplier count, uses wide RAM words, and preserves full-width codebook squares. All 117 original-photo C scores/masks match exactly; two complete RTL calls pass (656,435 cycles each for the small 80-side RTL fixture, not full-resolution FPS). Actual isolated synthesis uses 47,618 LUT, 65,515 FF, 218 DSP and 133 BRAM tiles. This does not prove whole-video fit or routed timing. The complete HDMI candidate is being implemented with ExploreArea; it has not been programmed and has no new measured detector FPS. HLS27/28 were rejected for 334 BRAM18; HLS29 RTL was deferred while reducing area. Their evidence remains under reports/v173/full_candidates.

The centered packed kernel requires encoder weights in [-127,127]. Its exhaustive mathematical check covers 16,646,400 activation/weight triples. Build preflight checks every convolution weight against the actual binary model and graph descriptors (529,760 bytes, zero -128 values); it rejects an incompatible model. The earlier general INT8 arithmetic primitive also covers -128, with all 16,777,216 triples checked, and remains separately documented.

Coarse on-board phase polling of accepted V172 found approximately 28.86 ms capture/wait, 12.52 ms preprocessing/first convolution, 39.76 ms depthwise convolution, 64.63 ms standard/pointwise convolution, 3.61 ms residual addition and 33.96 ms feature head/mask per frame. These host-polling estimates are not cycle-accurate timings. Both ARM cores were checked halted; there were no HLS control reads or per-frame start writes. This profiling is evidence for selecting future bottlenecks, not a new speed benchmark.
