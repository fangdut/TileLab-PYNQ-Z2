# V166：参照差分改进与实板工程验证

本版继续按花色保存良品参照，不训练新分类模型。**彩绘／多材质独立准确率尚未验收，完整参照算法尚未接入板端视频。** 当前三个验证范围分别留证，不能互相替代：

1. V166离线算法：对齐、光照标定和参照差异检测。
2. V164冻结检测器＋独立HDMI热插拔修正：50张开发图片通过实际HDMI、PL、DDR和以太网回放，掩码、报警与区域框和独立整数参考一致。17张裂纹报警、33张正常无报警；这些图片早已参与开发及训练，不是独立真实准确率。
3. V166独立窗口算术核：仿真与实际硬件自检另行记录。窗口生成、参照DDR、在线对齐、光照估计与区域分析仍不属于这份算术核的验证范围。

最终状态以[状态与验收证据](reports/v166/STATUS.json)和[图文报告](reports/v166/reference_report.html)为准。未满足的门槛会保留失败，不写成已验收。

## 算法变化与结果

保留V165的对齐和Q8光照补偿，将亮度与色度分开处理：亮度保留原始单像素细节，色度取3×3整数均值，减少JPEG彩色边缘伪影。额外保留超过良品局部色度变化范围的单像素变化，避免直接平滑掉纯颜色细线。边缘容差覆盖该3×3算子的空间范围；全部500×500像素仍参与检测，边界复制不等于裁边。

高／低阈值仍为18／9，所有颜色与边缘容差从良品参照计算，不使用当前图去扩大正常范围。本版没有改变被冻结的V159树模型或V164硬件分类器。

开发回放为174个程序构造用例，非照片盲测：

| 组别 | 数量 | 报警 | 拒判 | 说明 |
|---|---:|---:|---:|---|
| 原有正常扰动 | 36 | 0 | 0 | V165为2次误报、1次拒判 |
| 新增组合扰动正常图 | 36 | 0 | 0 | 包括压缩、位移、色偏和噪声组合 |
| 原有人工明暗线 | 24 | 24 | 0 | 最小GT覆盖100% |

72个构造正常用例没有误报，不等于真实误报率为0。最低裂纹覆盖和拒判率须公开。降低边缘容差曾补回弱线，也引入正常图误报，因此未采用；对应实验保留，不能用最好分项拼成最终成绩。

## 离线运行

需要Python、NumPy、Pillow。完整原生1280×720良品参照与当前图必须来自相同空间花纹和采集链路。实际自然纹理不能仅按“同材质”强行配对；错参照会拒判。

```powershell
python tools/reference_tile/reference_v166.py calibrate --image captures/pattern_A_good.png --material-id pattern-A --out build_local/reference_A_rev1
python tools/reference_tile/reference_v166.py inspect --bundle build_local/reference_A_rev1 --material-id pattern-A --image captures/pattern_A_current.png --out build_local/inspection_001
python -m unittest discover -s tools/reference_tile -v
python tools/reference_tile/audit_v166.py --out build_local/audit_v166_01
```

标定包不可覆盖，绑定算法、V165依赖和完整参数。成功比较输出JSON、掩码及叠加图；拒判退出码3、不输出掩码、`alarm=null`。`alarm=false`也仍需要人工复核。

## 验收门槛

沿用V164提出的工程目标：每个声称支持的花色／材质至少100块独立裂纹砖、400块独立良品砖；冻结参数、按实体砖隔离标定和盲测。图片级召回Wilson95%下限≥95%，误报Wilson95%上限≤1%。本版另外明确良品拒判及“报警或拒判”总失败上限≤1%，每张裂纹GT覆盖≥80%，防止用大量拒判或只检出一小段裂纹冲高数字。

这是项目工程目标，**不是比赛官方评分标准或奖项保证**。同一实体砖的重复照片、扩增图、自对照和人工裂纹不能充当独立实体砖数量。公开数据的正常／缺陷分类标签也不能自动证明空间花纹配对正确。

`tools/reference_tile/qualification_v166.py`会检查文件SHA、原生尺寸、实体砖身份隔离、源与标注声明、重复解码图像、代码和参数冻结，以及全部ROI标注覆盖。来源和标签真实性仍依赖人工审核，哈希不能证明标签真实。证据不足、异常数据或任一门槛失败都会拒绝验收，不能静默跳过失败图片。完整参照模式尚未集成，因此即便将来离线准确率通过，本原型也不会宣称整机已验收。

## 上板范围与使用

原视频链路把HDMI IN热插拔跟随HDMI OUT的显示器状态，OUT未接显示器时电脑可能识别不到开发板。本版在独立的传输实验包中解除了依赖，并让PS参考时钟在HPD之前启动。原V164 BIT/XSA/ELF及冻结源码保持原字节。

同时修复了工作站将PNG掩码当数组校验的问题，以及XSDB批处理返回0时可能隐藏Tcl错误的问题。下载现在必须看到唯一成功标记并完成寄存器检查。

独立传输实验包与原XSA不是同一个硬件导出，旧XSA仅用于未改动AXI地址映射；不能冒充匹配新BIT的XSA。单独的算术BIST镜像会临时替换应用，不包含视频或以太网工作站，完成后须恢复传输镜像。仅易失JTAG配置，没有写入Flash。

```powershell
python scripts/reference_v166/program_headless_transport.py --build releases/v166_headless_transport --xsdb D:/2025.2/Vitis/bin/xsdb.bat --address 192.168.33.10 --out build_local/program_headless_01
python host/single_tile_station.py --ethernet 192.168.33.10 --port 8770
```

IP按电脑实际有线网段设置。该工作站运行的检测器仍是V164，不导入离线V166参考检测器。实板输入是电脑HDMI显示已有公开照片，没有相机、实体瓷砖和固定光学系统验证。完整参照数据通路、区域逻辑与现场独立数据仍为验收阻断项。
