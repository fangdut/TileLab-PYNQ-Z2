# 可复用的 FPGA 验证工作流

适用于使用定点图像、信号处理或其他数组算子的 RTL/HLS 工程。工具不依赖瓷砖、ROI 或特定板卡。它们不执行综合、下载或远程写操作。

## 一、逐元素核对

```powershell
python skill/compare_arrays.py --expected reference.npy --actual captured.npy --out comparison.json
```

两个文件必须是非对象 NumPy 数组，形状及数据类型必须相同。任何不同都返回非零退出码；报告记录输入哈希、差异数量与首个差异坐标。不得通过自动裁边、类型转换或放宽阈值把错误变为通过。这里的相等只能证明所给数组之间的相等，不能证明文件来自硬件。

已验证效果见本工程整幅差异图回放：软件黄金参考与 FPGA 返回的数据另外计算并比较。推广到音频滤波、通信帧和定点神经网络时，替换数据来源和黄金参考即可。

## 二、部署文件的一致性

```powershell
python skill/verify_bundle.py --manifest deployment.json --root board
```

清单须含 `files` 字典，键为目录内相对路径、值为 SHA256。每项必须存在且完全一致，路径不得逃逸根目录。若目录中同时有 `system.xsa` 和 `system.bit`，还须核对 XSA 内嵌比特流；不能拿旧 XSA 证明新 BIT 的内容。

它检查完整性，不能代替可信签名、源代码审计、实际时序或功能验收。已在 TileLab 的匹配 BIT/XSA/ELF 工作流验证；其他板卡上的下载程序仍需单独验证。

## 三、从失败提炼的操作顺序

1. 将算法写成输入/输出、位宽、取整、饱和、边界、握手和复位合同。
2. 冻结可独立执行的黄金参考；用符号边界、饱和、阈值相等及随机数据生成向量。
3. 分别检查 C 仿真、RTL 仿真、综合布线和实际硬件；每步保留原始输出。HLS 估算频率不能替代实现时序。
4. 在下载前核对文件、源代码及版本身份；检查工具日志中的唯一成功标记。外层命令退出码为零不保证内部 Tcl 操作成功。
5. 为 DMA 输入和输出声明独立所有权。TCP 断线或超时不意味着 FPGA 已停止访问 DDR；完成或经过正确复位之前不能复用缓冲区。
6. 将结果先写入临时文件、同步到磁盘并原子替换，之后才确认接收。不要为清空队列而丢弃原始证据。
7. 在真实捕获像素上运行黄金参考。显示链路改变颜色时，原始图片不能替代实际输入。

这些经验来自本项目的 HDMI 热插拔依赖、旧事件误关联、PNG 解码接口错误、Tcl 失败被外层成功退出码掩盖，以及 HLS 测试台的 C/C++ 链接错误。每项都有对应脚本或原始失败记录；硬件计算通过也不等于真实场景准确率通过。

## 四、大模型协作提示词模板

先提供器件、接口、目标频率和冻结参考，然后依次要求：

- “列出软件与硬件之间所有必须一致的算术和边界规则；把未确定项单独列出。”
- “依据合同生成独立黄金参考和有意义的边界向量；不要根据 RTL 的输出反过来生成正确答案。”
- “给出资源、时钟域、缓冲区所有权与超时行为；用实际日志说明最差路径。”
- “在相同数据上分别报告计算核与端到端耗时，包含失败用例及拒判，不要混用仿真和硬件数据。”

失效条件：参考实现本身错误、标注不可信、输入域不匹配、文件来源未验证，以及模型产生了没有原始证据支撑的结论。必须由独立比对与实测约束模型回答。
