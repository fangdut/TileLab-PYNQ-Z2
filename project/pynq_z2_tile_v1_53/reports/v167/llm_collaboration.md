# LLM协作与纠错记录

本文件是本轮实际操作的摘要，不是逐字完整聊天记录，也不把摘要冒充原始工具输出。原始板测、算法汇总、固件测试与发布清单随包保留。

用户目标：先完成单片瓷砖项目，按花色保存良品参照，面向彩绘与多种材质，完成后备份GitHub。用户允许固定位置和光照，目前没有实体瓷砖、相机及光源；已连接PYNQ-Z2、HDMI IN和网线。最新指令原文：“那你倒是继续完善啊，什么时候能提交比赛项目了再说”。

本轮实际实现：从独立窗口算术自检转为250000像素完整DDR加速器；建立HLS C/RTL全图对照、整机Vivado时序约束、匹配ARM服务、实际HDMI回放、标定/拒判工作站和独立源码发布包。没有训练新分类模型。配准与区域分析仍在电脑，未声称完全自主设备。

纠错一：Windows HLS路径与C++顶层重复extern C使早期运行失败。修正路径和链接声明后重新运行C仿真、RTL联合仿真，并逐一验证联合仿真RTL与实际整机使用的10份HDL一致。失败不计入通过。

纠错二：上传2MB配对图耗时高。先改CRC表，改善有限；检查新平台BSP后发现TCP接收窗口仅2048字节。完整重建BSP为65535字节，实测上传、计算、返回中位数约145ms。计算核、网络和完整操作分别报告。

纠错三：仅依赖内部花纹配准导致条纹、平面和低对比度表面正常图被拒判。采用四条物理边界确定双轴位移，再检查内部花纹身份。光照拟合改为参照强度分层中位数，在缺少可辨识强度范围时固定单位增益，仅估计偏移。

纠错四：低阈值泛洪补全改善覆盖却扩张大量像素误检，未作为最终策略。最终仅用已经确认的候选播种，沿原始高阈值残差连接，保留初始掩码，不能新增图片级报警。失败研究汇总保留于research_history；该目录是历史算法，不能当当前版本成绩。

纠错五：运行中的Python模块不会自动更新。工作站增加源文件哈希变更拒绝动作，算法变动后重新启动、重新标定、重新执行全部实际HDMI回放，使用新部署清单绑定证据。

验证记录：board_records.zip包含实际原始采集、标定、差异图和输出；board_summary.json为逐例结果；protocol_faults.json为真实板端故障恢复；算法三个summary保留全部失败。check_provenance.py重新计算实际板端返回的每个分数。可复用skill提供文件及数组精确校验。

尚未解决：新程序用例有3张弱单像素线漏检，像素级精确率低于图片级检出率，不能混用。真实瓷砖、自然裂纹和相机光学准确率没有独立验证。报告与演示必须保留这些边界，后续取得实物后按同一花色分别统计误报、漏检、拒判。
