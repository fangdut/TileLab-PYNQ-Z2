# V174 深度卷积吞吐优化

本目录为硬件实验源。最新已上板验收的版本仍是 HLS39 / V173 R2，HDMI 6.666 FPS。候选版本只有完成 RTL、整机资源/时序和实板回归后才能晋升。

## 候选结构

`texture_bounded_dw.cpp`（冻结为 `../texture_v170/hls/frozen/v170_hls42.cpp`）保留原模型、阈值、整数精度与输出格式。

- 一个 `dot128` 物理阵列供普通卷积、深度卷积和近邻距离计算复用。深度 3×3 卷积按六个位置、三个位置分两步累加，移除原先独立的 `dw16` 实例。
- 行缓存改成三个 1024×128-bit 存储体；每体最多两个读请求，符合双口存储结构。逻辑缓存上限仍为 2048 个字，所有模型输入行宽不超过 224。
- 利用腾出的 DSP 把量化从四路提高到八路，每个像素由四次迭代改为两次。取整、饱和及 ReLU 保持原计算。
- 显式声明 32 次迭代的真实累加 RAW 依赖，生成 RTL 的读级 10、写级 41，写入在下一次同槽读取前完成。不能仅根据 C 仿真宣布流水线正确。

`test_parallel_dw.cpp` 直接包含实际候选源，用独立标量卷积核对边界、正负值（含 -128）、步长与环形行缓存。已核对 446430 个逻辑存储字、426 次 MAC 调用和 231936 个通道输出。该测试是离线检查，不代表硬件速度。

## 保留的失败

- HLS40 / `texture_parallel_dw.cpp`：尝试一步并行九个位置。C 117 张全值一致，但 HLS 为六个双口存储体估算 284 BRAM18，超过设备 280；流程在 RTL 和导出前拦截。未上板。
- HLS41 / `texture_two_step_dw.cpp`：资源估算降到 260 BRAM18、212 DSP，但旧的 `acc inter false` 导致读级 1、写级 42，而同槽间隔仅 32。RTL 仿真已实际报告此依赖冲突；在确认问题后终止该仿真，不计为通过，也未导出或上板。
- HLS42：有界地址和真实依赖约束；完整结果见后续 `reports/v174` 证据，未完成检查的阶段不能作为已通过。

`tools/fpga_texture_v170/check_mac_recurrence.py` 已加入构建前检查：对生成 RTL 的全部 16 个累加体核对读写级。HLS39、HLS42 静态通过，HLS41 被拒绝。这项检查补充完整 RTL 仿真，不能替代仿真与实板验证。

原始 MVTec Tile 117 张属于反复使用的公开开发集，不是独立盲测。所有运行检测计算仍安排在 PL，电脑 C++ 检查仅用于离线核对。
