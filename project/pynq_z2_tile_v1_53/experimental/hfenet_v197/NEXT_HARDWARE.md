# 下一阶段：完整帧整数引擎

当前只有完整离线整数参考、两个独立HLS单元和规范化的本地算子导出。
`export_program.py`导出71个算子（19卷积、17动态归一化）、72个张量及64字节
对齐的317120字节权重负载。它是迁移中间表示，不能给旧固件当model.bin上传。
模型参数／权重保留本地，公开保存源代码和身份哈希。

1. 用同一DSP乘加阵列依次执行5×5、3×3、膨胀5×1及1×1卷积，先以32或64路
   为候选，不同时保留旧217DSP网络和新完整网络。16位乘16位、单点最多800项，
   有符号48位累加足够容纳最坏整数和；之后使用已冻结的通道移位与最近偶数舍入。
2. DDR存放完整int16特征图和跳接数据。保守逻辑活跃张量峰值88MiB只是下界规划，
   还要实现真实静态地址分配、对齐、数据布局及越界检查。优先使功能可复现。
3. 卷积结果逐通道经过PL内求矩和归一化；不能在ARM处理InstanceNorm，也不能把
   动态统计换成固定BatchNorm。当前通用归一化单元HLS估计17DSP、15281LUT，
   需结合整机资源再做收窄／共享，不能直接相加估计当作布局成功。
4. 预处理单元HLS估计15.069ns，未满足原10ns目标。首次整机可评估50MHz功能
   原型，或在需要时修关键路径；必须绑定真实PS FCLK/AXI时钟并通过实际时序。
   不用标称100MHz包装未通过的实现，也不在功能验证前追10FPS。
5. 新输入契约必须支持256×1408原始扫描图，并按像素总数校验DDR容量。旧版
   1024单边限制保持有效直到新内核／固件一起验证。禁止主机偷偷缩放或裁图。
6. 先完整C输出比对、源绑定HLS／RTL，再构建整机、匹配模型CRC固件、实际上板。
   真实数据测试区分原图／裁取、作者验证／独立数据、软件／RTL／实板结果。
7. 稳定工作站和原视频流水线保留。新网络先走网口停驻检测；原尺寸图像如何进入
   HDMI系统仍需单独集成，不沿用旧8FPS作为新模型速度。保留未验证输入联锁，
   最后再考虑模型切换界面和最终比赛材料。

独立实拍和实体工件分组验证仍缺失。作者预训练模型对作者数据的80/80结果不是
最终验收，也不能证明任意彩绘／多材质或完整砖体都能检测。
