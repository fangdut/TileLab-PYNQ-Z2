# V175 采集与推理重叠流水线（尚未通过上板验收）

四槽所有权模块已接入 HDMI 流水线、DDR 写入器、独立的采集/推理状态机及结果寄存器。六组源文件绑定的 RTL 回归已通过，HW02 正在进行整机构建；尚无 V175 时序、上板或 FPS 结论。数值内核沿用已验收的冻结 HLS39，不使用板上速度下降的 HLS51。

目标是在 PL 内重叠采集与推理，减少串行等待。四个 4 MiB 输入槽从 `0x06000000` 开始，分别属于正在采集、最新就绪、正在推理、上一份已发布结果的输入。新采集可以替换尚未使用的就绪帧；绝不覆盖推理中或保留给快照的输入。

模块使用请求/授予接口。获得采集槽后一直持有，直到最后一个 DDR 写响应成功后提交；获得推理槽后一直持有，直到完整结果锁存完成。最新就绪帧可以被替换，因此不使用可能在背压期间改变负载的 AXI VALID 接口。同周期推理取帧先消耗旧就绪帧，采集提交再产生新就绪帧。

关闭使能后停止授予，丢弃未消费就绪帧，等待进行中的采集和推理结束，保留最后结果对应的输入。全系统复位必须同时复位采集与推理参与者，不能只重置队列后继续接收旧事务的完成响应。非法提交/完成会留下独立的粘滞故障位。

独立帧身份参考模型的 RTL 检查覆盖 20,150 个周期，包含快慢推理、槽复用、替换、坏帧、同时提交/完成、处理中关闭和恢复、采集与推理同时活跃时复位、同时协议错误。检查持续确认帧输入不被覆盖、结果/输入序号与 CRC 一致、排空及计数器一致。运行：

```powershell
python experimental/video_overlap_v175/test_queue.py --out D:/Vivado/TileLab_RealPhotos_20261020/v175_queue_fresh
```

输出目录须是全新路径。测试只验证队列所有权，不验证真实 DDR 响应、AXI 背压、时钟跨域或 CNN。

已完成的集成：

- 将采集和推理状态机分离，DDR 地址在各事务开始前锁存；DDR 写错误必须作为坏帧提交。
- PL 在 HLS 空闲时写入输入指针，再启动计算；AXI-lite 的 AW/W 背压分别处理，CPU 每帧启动计数保持零。
- 新增版本化的“最后推理输入基址/CRC/序号”寄存器，快照停机排空后读取该槽，逐图验收也按推理输入身份关联结果。
- 针对 AXI 背压、超时、写入失败、复位与停机进行总线模型集成仿真。缩小图像的集成用例包含 28 个在模拟推理期间完成的 DDR 写拍；CNN 在此用例中使用控制接口模型，不能据此报告实际吞吐。
- 视频寄存器版本为 `0x17500001`，`0x48` 保存最后推理输入基址，`0x4c` 保存替换就绪帧的计数。主机快照停机排空后按已发布槽读取，并核对 CRC、结果、输入基址及两核暂停状态。
- 控制时钟复位后延迟 200 ms 再拉高 HDMI HPD，避免依赖像素时钟锁定而无法启动。尚未证明该改动解决先前的显示枚举问题。

测试入口是 `test_queue.py`、`test_scheduler.py`、`test_pipeline.py --case writer|pipeline|video_regs|hpd`，输出必须是全新目录。`test_layout.py` 检查主机读取槽地址的版本和范围约束。`check_rtl_gate.py` 将六组通过记录绑定至全部 11 个 HDL 文件和测试平台；整机构建使用 `--video-variant overlap_v175 --video-rtl-gate <gate.json>`。默认串行版本不变。

HW01 在综合前因 Vivado BD 不支持以 SystemVerilog 文件作为 HPD 模块引用而终止。已改为 Verilog 封装并重跑 HPD 单元检查；失败记录保留。HW02 必须通过整机时序/DRC/FIFO Gray skew、117 张直接数值核对、真实 HDMI 图像与吞吐检查，以及 ARM 双核暂停和输入/结果身份核对后才能考虑提升为已验收版本。以上仿真通过不能当作吞吐提升证据。
